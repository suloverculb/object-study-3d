# 圖鑑式立體展示的視覺規格

## 已確認的基準

此分享版以文字規格與原始碼提供視覺基準，不附參考照片或預覽截圖：

- [頁面結構](../assets/baseline/index.html)
- [完整響應式樣式](../assets/baseline/src/style.css)

基準原始碼中的楊桃、星形圖示、學名與熟度文案屬於範例物品內容，製作其他物品時替換。模型及材質由程式產生，無需外部照片或貼圖。

## 色彩與字體

| 用途 | 基準值 |
| --- | --- |
| 畫布外的頁面背景 | `#f4f3eb` |
| 主要文字 | `#34432e` |
| 次要文字 | `#7c8172` |
| 細分隔線 | `#daddcd` |
| 強調色／焦點框 | `#718244` |
| 工具列底色 | `#eeeee3` |
| 選中按鈕 | `#fdfcf6` |
| 主要標題 | Noto Serif TC，600，桌面約 72–115px |
| 介面文字 | Noto Sans TC，400–600，約 9–13px |
| 外文副標 | Georgia 斜體，桌面約 18–25px |

維持上述色彩關係，物件本身可以有鮮明顏色。Google Fonts 為選用，保留系統 serif／sans-serif 後備。標題大小隨名稱長度調整，手機基準約 59px。

## 桌面結構

- `.app` 最大寬度 1800px、左右留白約 5%，以 `min-height: 100svh` 與縱向 flex 為起點，整頁高度貼齊目前視窗；內容隨可用高度調整，避免將頁尾推到視窗外。
- 頁首約 100px 高：左側細線圖示與中文品牌／小型英文副標，中間短句，右側卷次與「互動標本」。底部一條細線。
- 主區域約 30%／70% 雙欄。介紹欄垂直居中，放分類眉標、大名稱、外文副標、兩行觀察文案、標本編號及一個合適的主要參數控制。
- 右側畫布占據大部分空間，背景融入頁面。畫布上方是「形態觀察」及 `LIVE 3D`，下方是觀察模式編號與操作提示。
- 頁尾約 94px 高，頂部細線。中間為圓角工具列，兩側各一行小字。按鈕以淡色填底與細線 SVG 表達狀態。
- 模型下方使用柔和接地陰影。保持模型、標籤與控制列的視覺間距，避免陰影搶過物件。

## 填滿視窗與高度配置

- 主區域保留 `.main { flex: 1; min-height: 0; }`，由 flex 分配頁首、頁尾以外的剩餘高度。以瀏覽器實際可用的視窗高度判斷，不能只看螢幕解析度或寬度。
- 已修正的問題是寬度達 1600px 時將 `.main` 設為 `min-height: 760px`，加上 100px 頁首與 94px 頁尾，導致整頁至少 954px。原始碼基準已移除此規則；新展示不要因畫面較寬而強制增加主區域的最小高度。
- 畫布、介紹欄、留白與文字大小要配合可用高度。視窗較矮時，先調整間距與次要文案，再調整相應容器的最小高度，維持物件完整、控制列可操作。
- 透過版面伸縮消除溢出，不能以 `overflow: hidden` 隱藏超出的文字、模型或按鈕來通過檢查。字型載入及模式切換後仍須符合相同要求。
- 檢查尺寸與量測方式見 [Three.js 實作與驗證](three-workflow.md) 的「視窗高度與捲動檢查」。

## 手機配置

- 1000px 以下先縮小側邊留白，隱藏頁首中間短句與頁尾側邊文字。
- 640px 以下改成縱向布局：頁首、兩欄摘要區、主要畫布、底部操作列。
- 摘要左側名稱與外文副標，右側小型參數滑桿；若沒有合適參數，可讓名稱占滿寬度。
- 隱藏長介紹、標本說明和多餘裝飾，保留物品名稱、模型、模式、操作提示。
- 自動旋轉按鈕可縮為圖示，但必須保留 `aria-label`／`title`。畫布與工具列應在一般手機視窗中完整可用。
- 手機至少驗證 390×844、375×667，頁首、摘要、畫布及工具列總高度貼齊視窗且無捲軸。長名稱和多模式按鈕需另行檢查，必要時換行或調整工具列，避免照搬單一物品的固定尺寸。

## 版面中需要保留的細節

- `.scene` 使用 `position: relative`，canvas 使用 `position: absolute; inset: 0`。讓父容器決定尺寸，避免 canvas 反過來撐高容器並造成 `ResizeObserver` 迴圈。
- 查看 `src/style.css` 的媒體查詢和 `prefers-reduced-motion`，保持鍵盤焦點框及可讀的載入文字。
- 按鈕保持 `aria-pressed` 與視覺選中狀態同步；畫布有可理解的 `aria-label`、操作提示及鍵盤焦點。
- 學名只用於確有對應的生物物品。品牌可依物件類別改成「物件研究室」或適合的名稱，保留同一字體與階層。

## 新展示的檔案起點

若新增物品，將 `assets/baseline/` 的應用檔案複製至專案內的新展示目錄，再修改內容與模型。依保留的 `package-lock.json` 使用 `npm ci` 重現已確認的依賴版本。

基準不包含 `node_modules`、`dist`、快取或執行紀錄。不要把 `.agents` 複製進生成的應用，也不要把新展示的改動寫回凍結基準。
